# Юридические документы V-Tempe

**Это черновики для юриста, а не готовые документы.** Они составлены по коду
(`DATA_INVENTORY.md`, состояние на 2026-10-08) и не являются юридической консультацией.
Перед публикацией их должен проверить юрист по 152-ФЗ.

## Состав

| Файл | Что это |
|------|---------|
| `DATA_INVENTORY.md` | Реестр данных по коду: что собирается, где хранится, куда уходит. Основа для всех документов |
| `privacy-policy.md` / `.en.md` | Политика обработки персональных данных (ст. 18.1 152-ФЗ) |
| `terms-of-use.md` / `.en.md` | Пользовательское соглашение |
| `health-data-consent.md` / `.en.md` | Отдельное согласие на обработку данных о здоровье и трансграничную передачу (ст. 9, 10, 12) |
| `delete-account.md` | Страница удаления аккаунта для Google Play (RU + EN) |
| `site/` | Статический сайт, сгенерированный из Markdown: `index.html` (политика), `terms.html`, `health-data-consent.html`, `delete-account.html`, `en/` |
| `site/build_site.py` | Генератор сайта. Источник истины — Markdown. После правки запустите `python docs/legal/site/build_site.py` |

Русская версия документов имеет приоритет. Английская — перевод для магазинов и пользователей
с английским языком.

## Как это связано с приложением

- Ссылки на документы в приложении берутся из одной константы
  `shared/src/commonMain/kotlin/com/vtempe/shared/domain/legal/LegalDocuments.kt`
  (`BASE_URL`, сейчас заглушка `https://vtempe.example/legal`). После публикации сайта замените
  только `BASE_URL`.
- Версия текста согласия: `LegalDocuments.HEALTH_DATA_CONSENT_VERSION` (`2026-10-08`). Она же
  указана в `health-data-consent.md`. **При существенном изменении текста согласия поменяйте
  обе версии** — приложение повторно запросит согласие у всех пользователей.
- Согласие хранится на устройстве: факт, дата и версия (`prefs.healthDataConsent.*`).
- Без согласия запросы к AI не отправляются (`ConsentGatedAiTrainerRepository`,
  `ConsentGatedChatRepository`), приложение работает с офлайн-планами.

## Что должен сделать владелец

1. **Оформить оператора.** Зарегистрировать ИП или юрлицо, заполнить реквизиты, назначить
   ответственного за обработку ПДн (ст. 22.1), утвердить локальные акты (положение об обработке
   ПДн, перечень обрабатываемых данных, приказ о допуске, модель угроз, оценка вреда по приказу
   РКН).
2. **Уведомление в Роскомнадзор** (ст. 22) до начала обработки — через pd.rkn.gov.ru. Указать
   специальную категорию (данные о здоровье), цели, правовые основания, место нахождения БД,
   меры защиты.
3. **Уведомление о трансграничной передаче** (ч. 3 ст. 12) — отдельное уведомление: США
   (OpenRouter, провайдеры моделей, Google Firebase), Бельгия/ЕС (Google Cloud). Заполнить п. 6.4
   политики. Перед подачей запросить у получателей сведения о мерах защиты, как требует ст. 12.
4. **Решение по локализации** (ч. 5 ст. 18). Сейчас первичная запись и хранение ПДн граждан РФ
   идут в БД за пределами РФ (Google Cloud `europe-west1`). Это нарушение требования о
   локализации, его нельзя закрыть текстом политики. Варианты: перенести сервер и БД в
   российское облако (Yandex Cloud, VK Cloud, Selectel и др.) с последующей передачей за рубеж
   только того, что нужно AI; или держать первичную БД в РФ и дублировать за рубеж. Решение
   принять до публичного запуска в РФ. После переноса обновить `DATA_INVENTORY.md` и политику.
5. **Опубликовать сайт** `docs/legal/site/` по постоянному публичному HTTPS-адресу (GitHub Pages,
   Firebase Hosting, свой домен). Заменить `LegalDocuments.BASE_URL` в коде, собрать новую
   версию приложения.
6. **Google Play Console:**
   - App content → Privacy policy: URL `index.html`;
   - App content → Data safety: заполнить по `DATA_INVENTORY.md` (Health and fitness info,
     Personal info: e-mail, name; App activity; App info and performance — crash logs;
     Device or other IDs). Указать передачу третьим лицам (OpenRouter/провайдеры моделей), что
     данные шифруются при передаче и что пользователь может запросить удаление;
   - App content → Data safety → Data deletion: URL `delete-account.html`;
   - App content → Health apps declaration (если требуется для категории «Здоровье и фитнес»);
   - Target audience: 16+ / не для детей; Content rating — соответственно.
7. **App Store** (когда будет iOS): Privacy Nutrition Labels по тем же данным, URL политики.
8. **Проверить настройки OpenRouter**: логирование промптов выключено; рассмотреть
   `provider.data_collection = "deny"` (см. `DATA_INVENTORY.md`, п. 7.4). Указать сроки в
   документах.
9. **Сроки хранения на сервере**: настроить срок Cloud Logging, решить судьбу старых
   `payments.raw_payload` с данными карты (`DATA_INVENTORY.md`, п. 7.5).

## Вопросы юристу

- **Письменная форма согласия на СК ПДн** (ч. 4 ст. 9, п. 1 ч. 2 ст. 10). Сейчас согласие —
  отдельный документ, выражается флажком/кнопкой в приложении, фиксируются факт, дата и версия
  текста на устройстве. Достаточно ли этого как электронной формы, нужна ли простая электронная
  подпись по соглашению сторон и нужно ли хранить подтверждение согласия на сервере
  (сейчас — только на устройстве, у пользователей без аккаунта сервер их не знает).
- **Основание для трансграничной передачи в США** (страна без адекватной защиты): достаточно ли
  согласия субъекта в текущей редакции ст. 12.
- **Crashlytics без согласия** — законный интерес (п. 7 ч. 1 ст. 6) или вынести под согласие.
- **Возраст 16+** и проверка возраста.
- **Отзыв согласия и данные на сервере.** После отзыва приложение перестаёт отправлять данные
  в AI, но резервная копия (синхронизация при входе через Google) продолжает работать и
  удаляется только при удалении аккаунта. По ч. 5 ст. 21 после отзыва данные о здоровье нужно
  уничтожить за 30 дней. Нужно решение: либо при отзыве останавливать синхронизацию профиля и
  удалять его с сервера (изменение кода), либо обосновать иное основание.
- Порядок возврата средств при оплате через ЮKassa (соглашение, разд. 8).
